# Android test APK

`eas.json` now contains an internal-distribution **preview** profile producing an APK. It bundles JavaScript and does not need Expo Go, Metro, a tunnel or the computer to stay on. It still needs internet for Google, hosted scanning and cloud sync. Android builds do not require Apple developer approval.

No signed APK has been generated by adding this configuration. EAS project linking and signing require the owner's Expo account.

## Before the first build

1. Deploy **Deploy account deletion** in GitHub Actions and wait for green. The scanner and collection sync deployments remain separate.
2. In the project folder run `npx eas-cli@latest login`, then `npx eas-cli@latest init` to link/create Chase in your Expo account. This records the real EAS project ID; never invent one.
3. The hosted scanner's public Supabase URL and publishable key are bundled in `src/config/publicProject.json`. No `.env.local` or workstation proxy is needed. Complete public environment overrides remain optional; private CardSight/service-role keys must stay in Supabase.
4. Ensure Supabase Authentication → URL Configuration allows `chase://auth/callback?provider=google`. Google Cloud's authorized redirect remains Supabase's callback `https://vzjekkgyrdxzlhaupnrw.supabase.co/auth/v1/callback`.
5. Run `npx eas-cli@latest build --platform android --profile preview`. Let EAS generate/manage an Android signing key when prompted. Do not delete that key between updates.
6. Download the APK from the EAS build link and install on the trusted tester's Android phone. A different Wi-Fi is fine. Apple/iPhone cannot install this APK.

This preview APK explicitly enables **Simulate Pro** with `EXPO_PUBLIC_ENABLE_PRO_SIMULATION=true`, including the Profile toggle, saved local test plan and hosted scanner test-mode requests. Expo Go retains the toggle as before. The server must also have its existing Pro testing window enabled; this flag never grants a paid subscription or bypasses server budgets. Keep this flag out of future store/release profiles.

Use a disposable Google test account for the destructive deletion check. Confirm that its cloud collection disappears and the original guest collection and Organize remain. Do not use a valuable account as a deletion fixture.

## Windows: assisted build

Download/extract the latest GitHub ZIP, then double-click **preparar-apk.cmd**. It first validates public project settings, installs locked dependencies, opens Expo login/project linking, and requests the preview Android build. Answer EAS prompts using your own Expo account and let it generate a signing key if this is the first build.

The helper copies only the public connection values and explicit testing flag into `eas.json`'s preview environment. It never uploads `.env.local` or copies CardSight/admin secrets. This replaces the manual public-variable dashboard step above. Keep your local project changes from EAS init (`extra.eas.projectId`/owner) for future builds. Do not erase the Android signing key between versions. The final EAS link supplies the APK only after a successful cloud build; this helper is not itself an APK.

The production EAS profile uses hosted scanning too, without Pro simulation. Local proxy mode now requires explicit `EXPO_PUBLIC_SCANNER_BACKEND=local` and a development runtime. Even an installed release containing old pairing settings resolves to hosted scanning. The EAS/Expo login is only for compiling/signing; the app uses its own persisted Supabase guest/account session on the phone.
